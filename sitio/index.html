Para qué sirve

Esta guía complementa DES-EST-016 v2 (Estándar control de código fuente) y ARQ-PRO-001 v1 (Procedimiento control de versiones). Donde esos documentos se contradicen o no cubren un caso, se aplica lo que dice esta guía; las diferencias están en Por qué lo hacemos así. Cada regla se probó en la prueba de concepto (POC-RAMAS.md), cuya evidencia está en evidencia\<escenario>\.

Validador de nombre de rama

Escriba o pegue el nombre de una rama. Se valida con las dos expresiones de la guía y el límite de 60 caracteres, y si falla se explica qué parte falla. Las expresiones y las reglas de escritura están en Referencia › Nomenclatura.

Tres reglas que sostienen todo lo demás

  1. Toda rama de trabajo nace de un tag (nunca de la rama sbx). El hotfix nace del tag que está en producción; el resto, del último tag. R2
  2. Antes de crear un tag, la rama incorpora el último tag existente (regla de cadena). R3
  3. El tag se crea en la rama de trabajo, antes de completar el PR a sbx. R4
